## Mapping procedure
1. Priority order: **organization system, then selected public system, then custom component**.
2. For each Figma component instance or frame, find the matching component and variant/props. Match by purpose (button, input, card, dialog) rather than by name only.
3. Use the library props, slots and theming before writing custom CSS. Do not override internal library styles with `!important` or deep selectors.
4. If no match exists, build a small custom component from library primitives and list it under "Custom components" in the summary.

## Tokens
- Resolve each Figma variable/style to a design token (color, spacing, radius, typography, elevation) and reference the token, not the raw value.
- If a Figma value has no token, use the nearest token when the difference is trivial; otherwise flag it as "token gap".
- Support light/dark themes when the design system does.

## Output
A mapping table in the final summary: `Figma element | Component | Props/variant | Tokens`.
